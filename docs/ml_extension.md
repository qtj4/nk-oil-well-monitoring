# Descriptive event characterization (chosen option 2)
Task: explain a candidate sensor distribution shift; no failure prediction. Input: existing candidate and original same-well/same-parameter observations. Output: 7-day before/after median, standard deviation, level delta, standardized delta if nonzero preceding variance, source-flag density, missing-or-null fraction, days to next candidate or scope end and censoring status. Missingness includes sample selection and scope truncation. Duration is distance to another candidate, not verified physical regime duration.

This is retrospective analytics, not a trained classifier. Future context is intentionally used only for explanation, never as a detector input or to choose thresholds. Daily candidate timestamp denotes bin start and becomes available next day. Main detectors fit median/MAD on official train only; training-era events are descriptive, frozen-reference evaluation is test-only. No accuracy claims or clusters named as faults.

Evidence: `results/<run_id>/event_characterization.csv` and `characterization_benchmark.json` from actual data. `tests/test_product.py` verifies exact synthetic before/after delta and coverage, persistence, note escaping and real-data UI review→report flow in temporary SQLite. Sample run indexed 215 candidates (all train+test methods combined); see CSV for exact counts. RSS measurement is 10-ms sampling and can miss short peaks.
